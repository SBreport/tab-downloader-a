# 탭 다운로더 A 저장소 운영 규칙

## 기본 흐름

1. `main`은 직접 사용 가능한 상태만 유지합니다.
2. 사이트 추가나 Helper 변경은 `feature/<짧은-이름>` 브랜치에서 작업합니다.
3. `npm test`와 `npm run check` 통과 후 `main`에 병합합니다.
4. 사용자 동작이 바뀌면 `CHANGELOG.md`와 관련 문서를 함께 갱신합니다.
5. 배포 기준점에는 manifest 버전과 같은 `vX.Y.Z` 태그를 붙입니다.

## 커밋 권장 단위

- `feat(adapter): ...` 사이트 지원
- `fix(helper): ...` Helper 오류 수정
- `fix(ui): ...` 사이드 패널 수정
- `test: ...` 회귀 테스트 추가
- `docs: ...` 안내·변경 기록 수정
- `chore(release): vX.Y.Z` 릴리스 준비

다운로드 파일, 캐시, 개인 설정, 실행 파일, `.pem` 개인키는 커밋하지 않습니다. 첫 원격 저장소는 GitHub 비공개 저장소로 생성합니다. 원본 프로젝트와 별도 origin을 사용합니다.
